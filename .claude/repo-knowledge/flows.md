# Flows
1. Install single VPS: start.sh --service -> install_release_binary -> webdep --pair-local -> write webdep-core + webdep-node units -> systemctl enable/restart.
2. Join worker: panel POST /api/cluster/enroll-tokens -> cluster/manager.rs create_enroll_token builds join/service/fresh_vps commands -> UI cluster.js shows freshVpsCommand -> on VPS2 start.sh --service --node --join --token -> webdep --enroll-only writes data/node-state.json -> webdep-node unit.
3. Deploy: /api/projects/* -> deployer (builder, worker, retention) -> runtime (process/container supervisor) -> caddy reload.
4. Create app: POST /api/projects or /api/databases -> needs is_admin or panel create_<kind> (or legacy *_manage) -> port from node pool (none free => 409, no app row) -> non-admin gets owner grant (grants::grant_owner) -> access::after_change.
5. Port/IP/limit change (admin): api/ports.rs -> UPDATE projects -> propagate_project_change (process env, Caddy write+reload or remote project.ensure + sync_remote_caddy, firewall) -> restart if running (limits/port).
6. Firewall: pool change -> ports::firewall_targets -> apply_on_node (local sync_firewall_ports or RPC firewall.ports) -> nodes.firewall_state ok/pending/failed; resync on node Register and Core start.
7. Upgrade: boot -> pending migrations? -> backup_before_migrate (pg_dump pre-upgrade-*.dump, keep 5) -> run_migrations (ignore_missing for rollback).
9. Backup (local app): POST /projects/:id/backup -> row status=running -> background task -> cluster::archive::pack_backup_archive to <data>/backups/apps/project-<id>/backup-<bid>.tar.gz.part -> rename -> finish_ok (size, files, sha256). Remote app: same row, node RPC project.backup_archive builds it on the VPS. Restart cuts off running rows -> recover_interrupted marks them failed.
10. Restore (replace, never merge): POST /projects/:id/backups/restore -> start_restore (one per app: backups::begin_restore; blocks deploy/backup) -> restore_in_place -> backups::restore_files: verify sha256, stage in <deploy>/.restore-tmp, stop app, swap_in (rename live -> .pre-restore/<label>-<ts>, staged -> live, rollback on failure), env replaced (set_bulk_env replace_all), app restarted. Sources: archive or older folder backup (files/ + backup.env); kind env-only or no files dir restores env only. Remote: node RPC project.backup_restore. Status via GET restore-status (in-memory).
12. DB backup: POST /databases/:id/backup -> database_backups row running -> task db_backups::create_dump (pg_dump -F c to data/backups/databases/db-<id>/backup-<bid>.dump, sha256) -> complete/failed. Restore: db_backups::restore_dump verifies sha256, then ONE psql transaction: BEGIN, drop all schemas, replay pg_restore plain SQL, COMMIT only if pg_restore exited 0 (else rollback, DB untouched). DB must be running; local node only.
13. App isolation (opt-in WEBDEP_ISOLATE_APPS=1, Linux root): runtime/isolation.rs wraps app starts (runtime/process.rs) and builds (deployer/builder.rs) in unshare (pid/mount/ipc/uts), tmpfs over data+cwd with the app folder bound back, private /tmp, setpriv to uid/gid 65534.
14. Limit watch: api/limit_watch.rs run() every 15s; each running app with limits is checked ~20s after (re)start then every 120s: disk over -> stop + event, memory/cpu >=95% -> event (10 min cooldown, reset on restart); supervisor records ram_start events for crashes with a memory limit; UI public/js/limit_alerts.js polls /api/limit-events and shows state.js showLimitDialog. Start refusals are tagged [app-limit:disk|backups|ram_start]. runtime/limits.rs memory_hints sets JAVA_TOOL_OPTIONS/NODE_OPTIONS under a memory limit.
8. Hourly: main.rs loop -> maintenance::prune_audit, daily_backup_if_due, check_port_pools -> notify (webhook via curl).
